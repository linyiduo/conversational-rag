# 上下文构造

Top-K 检索返回若干文档块之后，把这些块和这一轮对话拼成给大模型的提示词。实现在 `src/generate.py` 的 `format_context` 和 `build_prompt`。`scripts/run_baseline.py` 在 `generator.generate(...)` 里调用它们。`--retrieve_only` 打开时不走这一步。

检索用的那段字符串不进提示词。提示词里的问题是原来的 `question`，历史是 `example.history_text`，文档是检索命中的全文。

## 文档块怎么排

命中按分数从高到低排，第 1 名是 `[1]`。有标题时一块是：

```text
[1] 标题
正文
```

没有标题就只有 `[1]` 和正文。QReCC、TopiOCQA 的语料没有标题，MultiDoc2Dial 有。块与块之间空一行。

正文用的是检索到的完整文字。结果文件里 `retrieved.text` 只留前 300 个字符，那个截断不进提示词。分数和 `is_gold` 也不写进提示词。

所有块加起来不超过 3500 个字符。下一块放进去会超，就停，后面的名次丢掉。这个上限写在 `format_context` 的 `max_chars`，命令行改不了。

## 提示词的样子

历史同样取最近 `--max_history_turns` 条，默认 6，一条是一句发言。这里只放这一轮之前的发言，当前问题写在后面的 `Question:`，不会再在历史末尾重复一次。还没有历史时，整段 `Dialogue history` 省掉。

```text
You are a helpful assistant. Answer the user's question using only the given context. If the context is insufficient, say you do not know.

Dialogue history:
User: 上一句用户的话
Agent: 上一句系统的回答

Context:
[1] 正文
[2] 正文

Question: 当前问题
Answer:
```

提示词是英文。模型被要求只根据 Context 回答，Context 不够就说不知道。

## 改哪里

文档块的编号、标题和 3500 字符上限在 `format_context`。提示词的说明文字、历史和问题的位置在 `build_prompt`。

`run_baseline.py` 里传给 `generator.generate` 的是原来的 `example.question` 和 `example.history_text`。要换掉送进提示词的问题或历史，改这一次调用。
