# 索引

`indices/` 由 `scripts/build_index.py` 在本机生成，实现在 `src/index.py` 的 `build_index`。删掉后可以重建，不影响原始数据。原始数据见 [数据集.md](数据集.md)。

## 读入哪些文本

| 数据集 | 读取位置 | 一条记录是什么 |
|---|---|---|
| MultiDoc2Dial | `multidoc2dial/multidoc2dial/multidoc2dial_doc.json` 的 `doc_data` | 一篇文档的 `doc_text`，编号用 `doc_id`，标题用 `title` |
| QReCC | `qrecc-passages/data/*.parquet`，按文件名排序 | 一行的 `id` 和 `contents`，没有标题 |
| TopiOCQA | `topiocqa-collection/data/*.parquet`，按文件名排序 | 一行的 `id` 和 `contents`，没有标题 |

空文本会丢掉。`--max_passages N` 表示按上面的顺序只取前 N 条，再进入切分。当前 QReCC 和 TopiOCQA 的索引都是 `N = 20000`；MultiDoc2Dial 没有设上限。

读进来之后、切分之前，预处理只做两件事：去掉首尾空白，丢掉空文本。没有按句子切开，也没有去重。MultiDoc2Dial 的 `doc_text` 已经是从网页抽出的纯文字；原来哪一段是标题，记在 `spans` 里（例如 `tag` 为 `h2`）。建索引时不用 `spans`，标题和正文一样切。

## 怎么切分

实现在 `src/chunking.py`，按字符滑窗，不按词或 token：

- 去掉首尾空白后，长度不超过 512 的整段保留，编号写成 `原编号#0`
- 更长的从开头每次取 512 个字符，下一块起点回退 64 个字符，所以相邻块重叠 64 个字符，步长是 448
- 编号依次是 `原编号#0`、`原编号#1`……
- `meta` 里记下 `source_id`（切分前的编号）和 `chunk_id`

重叠是为了不让跨在切分边界上的句子两边都不完整。没有重叠时，答案若正好被切开，前一块的结尾和后一块的开头都对不上问句。回退 64 个字符后，这段文字同时出现在相邻两块里。

64 没有在这三个数据集上调过。常见做法是重叠取块长的大约一到两成，这里是 `64 / 512 = 12.5%`。LangChain 的默认切分器也是这个量级（块长 1000、重叠 200）。再小，稍长的句子仍可能被切断；再大，重复文本变多，块数和检索时的重复命中都会上去。当前按字符切，不看句号，所以这只是一个够用的默认值，建索引时可以用 `--chunk_overlap` 改。

默认就是这组参数：`--chunk_size 512 --chunk_overlap 64`。

## 怎么变成向量索引

一块文本对应一个向量，顺序和后面 `passages.jsonl` 的行号一致。第 i 块的原文在 jsonl 第 i 行，它的向量是 `index.faiss` 里的第 i 条。索引里不存文字。

送进模型的字符串：有标题时是 `标题 + 换行 + 正文`，没有标题就只有正文。QReCC 和 TopiOCQA 的语料没有标题，所以编码的就是切出来的那段字。

模型是 `models/all-MiniLM-L6-v2`（Hugging Face 上的 `sentence-transformers/all-MiniLM-L6-v2`，约 88MB）。第一次建索引或检索时，如果这个目录里还没有权重，会自动下载到这里；已经有了就直接用。它做三步：

1. 六个 Transformer 层给每个 token 一个向量。模型最多看 256 个 wordpiece，多出来的末尾直接丢掉。切分用的是 512 个字符，英文里通常到不了 256 个 token，所以多数块不会被截断。
2. 对这些 token 向量做平均，得到一个 384 维的向量。用的是平均，不是取第一个 token。
3. 再除以向量自身的长度，使长度为 1。`encode` 时也开了 `normalize_embeddings=True`，写进索引的是 `float32`。

因为每条向量长度都是 1，两条向量的内积就是它们的余弦相似度，范围大约在 -1 到 1，越接近 1 越像。问句检索时用同一个模型、同一种归一化编成一个 384 维向量，再和库里每一条做内积。

模型只负责把文字变成向量。要在几万条向量里找出和问句最像的 K 条，并在下次运行时不用重新编码，就需要一个向量库。这里用 FAISS：它专门做这件事，一次算完和全部向量的内积并返回最大的 K 个编号，结果还能写成 `index.faiss` 这个文件。当前块数从几千到几万，精确比较一次就能扫完，所以先用最简单的 `IndexFlatIP`，避免近似索引把真正相关的块排丢。以后如果把 QReCC、TopiOCQA 的全量语料都编进来，向量会到千万级，可以仍在 FAISS 里换成近似索引，检索和生成的代码不用改。

`IndexFlatIP` 里，`Flat` 表示向量原样存放，没有聚类，也没有压缩；`IP` 表示用内积比较。检索时和全部向量都算一遍，取内积最大的 K 条，返回的编号就是 `passages.jsonl` 的行号。

编码按批进行：先攒 256 块（`batch_size * 4`，`batch_size` 默认 64），整批编码后再攒下一批。全部编完后一次写入索引，不是编一块写一块。

## 写出的三个文件

都在 `indices/<dataset>/`，同一次运行覆盖旧文件。

| 文件 | 内容 |
|---|---|
| `index.faiss` | 向量本身。第 i 个向量对应 `passages.jsonl` 的第 i 行 |
| `passages.jsonl` | 切分后的块。每行有 `pid`、`text`、`title`、`meta`。检索命中后用它拼上下文 |
| `meta.json` | `embed_model`、`chunk_size`、`chunk_overlap`、`num_chunks`、`max_passages`、`dim` |

当前块数：MultiDoc2Dial 5334，QReCC 75701，TopiOCQA 27116。后两个块数大于 20000，是因为长文档被切成了多块。

## 重建

```bash
python scripts/build_index.py --dataset multidoc2dial
python scripts/build_index.py --dataset qrecc --max_passages 20000
python scripts/build_index.py --dataset topiocqa --max_passages 20000
```

去掉 `--max_passages` 会按 parquet 文件名顺序，把该数据集磁盘上的检索语料全部编入索引。
