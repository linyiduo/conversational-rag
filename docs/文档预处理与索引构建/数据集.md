# 数据集

`data/` 只放在本机，已被 `.gitignore` 忽略。下面这些都是下载来的原始数据。索引怎么生成见 [索引.md](索引.md)。

| 路径 | 内容 |
|---|---|
| `multidoc2dial/` | MultiDoc2Dial 官方压缩包解压结果。含文档 `multidoc2dial_doc.json`，以及 train / validation / test 对话 |
| `qrecc/train.jsonl`、`qrecc/test.jsonl` | QReCC 对话。内容来自 Hugging Face `slupart/qrecc`，为避开 `datasets` 版本不兼容，在本机转成了 JSONL，字段未改。官方只有 train 和 test |
| `qrecc-passages/` | QReCC 检索语料，55 个 parquet，约 29GB，全量 |
| `topiocqa/` | TopiOCQA 对话，`topiocqa_train.jsonl` 与 `topiocqa_valid.jsonl`，全量。官方没有独立 test |
| `topiocqa-collection/` | TopiOCQA 使用的 Wikipedia 检索语料，6 个 parquet，约 6.7GB，全量 |

一条样本是用户的一轮，不是整段对话。当前这句话单独放，之前的发言另放。要检索的文档不在对话文件里。

## MultiDoc2Dial

人去办社保、退伍军人事务、车管所、助学贷款时的对话，网站域名是 `ssa`、`va`、`dmv`、`studentaid`。一段对话是 `turns` 数组，每句自己标着 `user` 或 `agent`。例如：

```text
user   What would my widower receive in benefits?
agent  In the event of your passing, your widower would start receiving reduced benefits at age 60 or full benefits if they are at retirement age or older.
```

没有名叫 `Answer` 的列。走到某一句 `user` 时，这句是当前问题，更早的 `turns` 是历史，紧跟着的下一句 `agent` 就是标准答案。也没有 `Truth_rewrite` 这种改写句。

每句还有 `da`（这句话在对话里起什么作用，例如 `query_solution`）和 `references`。`references` 里的 `doc_id` 指向该看的网页，`id_sp` 指向网页里的哪一段。网页在 `multidoc2dial_doc.json` 里，一篇有标题和整页正文 `doc_text`。官方有 train、validation、test。

## QReCC

开放域对话。每一行是一轮，字段是平的：

```text
Context[0]      What is a physician's assistant?
Context[1]      physician assistants are medical providers ...
Context[2]      What are the educational requirements ...
Context[3]      Complete your bachelor's degree ...
Question        What does it cost?
Truth_rewrite   What does it cost to become a physician's assistant?
Truth_answer    这一轮的标准答案
Truth_passages  答案所在网页段落的编号
```

`Context` 没有角色名，偶数条是用户以前问的，奇数条是当时的回答。当前问题在 `Question`，不在 `Context` 里。`Truth_rewrite` 是已经补全的那一句，只有这个数据集有。要检索的段落在 `qrecc-passages/`，约 29GB。官方只有 train 和 test。

## TopiOCQA

开放域对话，话题沿着维基百科的章节往下走。一行的排法和 QReCC 一样，是 `Context` 加当前 `Question`。验证集第 1 段对话的第 3 轮：

```text
Context[0]      when will the new dunkirk film be released on dvd
Context[1]      18 December 2017
Context[2]      what is this film about?
Context[3]      Dunkirk evacuation of World War II
Question        can you mention a few members of the cast?
Answer          Fionn Whitehead, Tom Glynn-Carney, Jack Lowden, Harry Styles
Topic           Dunkirk (2017 film)
Topic_section   Introduction
Gold_passage    标题 Dunkirk (2017 film) [SEP] Introduction，正文是这一节的维基文字
```

当前这句没有说出是哪部电影。`Gold_passage` 把该看的那一节直接带在这一轮里，标题用 `[SEP]` 把页面名和章节名接在一起。没有 `Truth_rewrite`。检索语料在 `topiocqa-collection/`，约 6.7GB。官方是 train 和 valid，没有单独的 test。

重新下载：

```bash
python scripts/download_datasets.py
```

对话文件只在跑实验时当问题使用，不参与建索引。建索引读的是文档或检索语料：

| 数据集 | 建索引时读取 |
|---|---|
| MultiDoc2Dial | `multidoc2dial/multidoc2dial/multidoc2dial_doc.json` 里每篇文档的 `doc_text`，编号是 `doc_id`，标题是 `title` |
| QReCC | `qrecc-passages/data/*.parquet` 的 `id` 和 `contents`，按文件名排序，没有标题 |
| TopiOCQA | `topiocqa-collection/data/*.parquet` 的 `id` 和 `contents`，按文件名排序，没有标题 |

## 加载时留下了什么

三个加载器在 `src/data/`，把一轮收成同一种样本：`question`、`history`、`answer`，外加可选的 `rewrite` 和 `gold_passage_ids`。跑基线要用的问句、历史和标准答案都读进去了。

| 数据集 | 已经读入 | 没有读入 |
|---|---|---|
| MultiDoc2Dial | 当前 `user` 句、之前的 `turns`、下一句 `agent`（当作答案）、`references` 的 `doc_id` 和 `id_sp`。`id_sp` 对应 `spans` 里的字符位置，再按建索引的同一套切块，写成 `doc_id#k` | `da`、网页 HTML |
| QReCC | `Question`、`Context`、`Truth_answer`、`Truth_rewrite`、`Truth_passages`，以及检索语料的 `id` 和 `contents` | `Answer_URL`、`Conversation_source` |
| TopiOCQA | `Question`、`Context`、`Answer`、`Gold_passage` 的 `id`、标题和正文、`Topic`、`Topic_section`，以及检索语料的 `id` 和 `contents` | `Rationale`、`Additional_answers`、`is_nq`。没有改写列，所以 `rewrite` 为空 |

标准段落和命中的 `pid` 这样比，实现在 `src/matching.py` 的 `hit_is_gold`，检索结果里每一条有 `is_gold`：

- MultiDoc2Dial 的 `gold_passage_ids` 是 `doc_id#k`，和索引里的切块号同一套。一块命中当且仅当它的 `pid` 在这个列表里。
- QReCC 的 `Truth_passages` 是切块前的段落编号。命中的 `pid` 是 `段落编号#k`，比较时用 `#` 前面的那段。
- TopiOCQA 的 `Gold_passage.id` 是维基页面号，检索语料的编号是另一套从 1 开始的数字，语料里没有页面号这一列，无法改写成同一个编号。`Gold_passage.text` 会留下来。一条命中的正文去掉空白后能在这段金标正文里找到，就记 `is_gold`。
