## 下载

数据和模型已经在本机时不用再跑。缺文件时：

```bash
python scripts/download_datasets.py
```

会下载三个数据集的对话，以及 QReCC、TopiOCQA 的检索语料。

检索向量模型不用单独下。第一次执行 `build_index.py` 或 `run_baseline.py` 时，如果 `models/all-MiniLM-L6-v2` 里还没有权重，会自动下载到这个目录（约 88MB）。已经有了就跳过。

生成模型缺失时：

```bash
mkdir -p models/Qwen2.5-3B
hf download Qwen/Qwen2.5-3B --local-dir models/Qwen2.5-3B --max-workers 8
```

## 建索引

```bash
python scripts/build_index.py --dataset multidoc2dial
python scripts/build_index.py --dataset qrecc --max_passages 20000
python scripts/build_index.py --dataset topiocqa --max_passages 20000
```

去掉 `--max_passages` 会把该数据集磁盘上的语料全部编进索引。QReCC、TopiOCQA 全量索引耗时很长。

| 参数 | 默认 | 含义 |
|---|---|---|
| `--dataset` | 必填 | `multidoc2dial`、`qrecc`、`topiocqa` |
| `--embed_model` | `models/all-MiniLM-L6-v2` | 向量模型目录 |
| `--chunk_size` | `512` | 每块字符数 |
| `--chunk_overlap` | `64` | 相邻块重叠字符数 |
| `--batch_size` | `64` | 编码批大小 |
| `--max_passages` | 不限制 | 最多读多少条原始文档 |
| `--device` | `cuda` | `cuda` 或 `cpu` |
| `--data_root` | `data` | 数据根目录 |

输出在 `data/indices/<dataset>/`，三个文件分别是向量、原文和参数。切分和编码的细节见 [索引](文档预处理与索引构建/索引.md)。

## 跑基线

先有对应数据集的索引，再跑 `scripts/run_baseline.py`。它从指定的对话划分里取若干轮：用 `--query_mode` 拼检索词，取出 Top-K 文档，再交给 Qwen 写答案。不写 `--query_mode` 时是 `question`，只拿当前这句去检索。`--max_examples` 是最多跑多少轮，不是把这一份对话全部跑完。

检索并生成。下面这条跑 MultiDoc2Dial 的 validation，最多 10 轮：

```bash
python scripts/run_baseline.py --dataset multidoc2dial --split validation --max_examples 10
```

只检索、不加载 Qwen。结果里的 `prediction` 是空的：

```bash
python scripts/run_baseline.py --dataset multidoc2dial --split validation --retrieve_only --max_examples 20
```

三个数据集各看一小段。划分用的是官方拿来评估的那一份，不是训练集：MultiDoc2Dial 和 TopiOCQA 用 validation，QReCC 没有 validation，用 test。

```bash
python scripts/run_baseline.py --dataset multidoc2dial --split validation --max_examples 10
python scripts/run_baseline.py --dataset qrecc --split test --max_examples 10
python scripts/run_baseline.py --dataset topiocqa --split validation --max_examples 10
```

同一份数据上比较三种检索词。QReCC 才有金标改写，所以用它来比。三次的 `--query_mode` 不同，会写成三个文件。

```bash
python scripts/run_baseline.py --dataset qrecc --split test --query_mode question --max_examples 50
python scripts/run_baseline.py --dataset qrecc --split test --query_mode history --max_examples 50
python scripts/run_baseline.py --dataset qrecc --split test --query_mode rewrite --max_examples 50
```

| 参数 | 默认 | 含义 |
|---|---|---|
| `--dataset` | 必填 | `multidoc2dial`、`qrecc`、`topiocqa` |
| `--split` | `validation` | 用哪一份对话，见下表 |
| `--query_mode` | `question` | 检索时用哪段文本，见下表 |
| `--top_k` | `5` | 检索条数 |
| `--max_examples` | `20` | 最多跑多少条对话 |
| `--max_history_turns` | `6` | 最多带上几轮历史 |
| `--llm_model` | `models/Qwen2.5-3B` | 生成模型目录 |
| `--embed_model` | `models/all-MiniLM-L6-v2` | 向量模型目录，一般不用改 |
| `--max_new_tokens` | `128` | 最多生成多少 token |
| `--output` | 自动命名 | 自定义 JSONL 路径 |
| `--retrieve_only` | 关闭 | 只检索 |
| `--device` | `cuda` | `cuda` 或 `cpu` |
| `--data_root` | `data` | 数据根目录 |

结果默认写到：

```text
results/<dataset>_<split>_<query_mode>_k<top_k>.jsonl
```

同名文件再跑会被覆盖。文件是一个 JSON 数组，每一项是一轮，字段换行展开：

| 字段 | 内容 |
|---|---|
| `question` | 当前这句用户的话 |
| `query` | 实际拿去检索的字符串 |
| `gold_answer` | 数据里的标准答案 |
| `prediction` | 模型生成的答案。`--retrieve_only` 时为空 |
| `retrieved` | K 条命中：`pid`、`source_id`、`score`、`is_gold`、`title`，正文只留前 300 字 |
| `gold_passage_ids` | 标注的标准段落编号 |

`is_gold` 怎么判定见 [检索](Top-K%20检索/检索.md)。

上面那条 MultiDoc2Dial、最多 1 轮的命令，终端上是这样。问题和生成结果都只印前 180 个字符：

```text
[1] 1409501a35697e0ce68561e29577b90a:1
Q: My insurance ended so what should i do
query_mode= question -> My insurance ended so what should i do
gold: You will need to get insurance or we will suspend your registration and license
pred: If your insurance ends, you should surrender your vehicle plates to the DMV immediately. ...
top1: Respond to DMV insurance letters and orders#3_0#2 0.49409711360931396
wrote 1 examples to results/multidoc2dial_validation_question_k5.jsonl
```

`results/multidoc2dial_validation_question_k5.jsonl` 里是一个数组，这一次只有 1 项。`query` 和 `question` 相同，因为这是第一句、又用了 `question`。`prediction` 是完整的第一段，比终端上长。`retrieved` 有 5 条，按 `score` 从高到低，这一轮 5 条的 `is_gold` 都是 `false`：检索到的是保险信函那篇文档，标注的两块在 `Top 5 DMV Mistakes and How to Avoid Them#3_0`。

```bash
python scripts/build_index.py -h
python scripts/run_baseline.py -h
```

## 数据划分

`--split` 选择对话样本，不改变索引。

| 数据集 | 可用取值 | 说明 |
|---|---|---|
| `multidoc2dial` | `train`、`validation`、`test` | 三份都有。`valid` 和 `dev` 等同 `validation` |
| `qrecc` | `train`、`test` | 没有 validation。写成 `validation` 时会改用 `test` |
| `topiocqa` | `train`、`validation` | 没有独立 test。写成 `test` 时会改用 `validation` |

调参用各数据集的非训练集。MultiDoc2Dial 报最终数字时用 `test`。

## 查询模式

`--query_mode` 决定送进检索器的文本。三种拼法的例子见 [查询构造](Query%20构造/查询构造.md)。

| 模式 | 检索文本 |
|---|---|
| `question` | 只使用当前这一轮的问题。这是默认值 |
| `history` | 最近若干句发言，再加上当前问题 |
| `rewrite` | QReCC 用数据里的金标改写；另外两个数据集没有这列，会退回 `history` |
